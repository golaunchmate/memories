### COORDINATION ARCHITECTURE - KEY INSIGHT

**Michael's Breakthrough:**
"We keep trying to coordinate agents... We treat... we keep trying to get at an agent's memory through the agent."

**The Solution:**
- Decouple memory from individual agents
- Store in shared repository (GitHub or similar)
- "Sleep time across many different agents" - periodic synthesis
- Read-only first (dashboards), then read-write (synchronization)

**Architecture Pattern:**
```
Individual Agent Memory → Shared Repository → Synthesizer Agent → Updates back to agents
```

**Why It Matters:**
- Enables Cameron/Erica reviews without manual agent queries
- Dashboard views of all teams
- Cross-agent insights
- "Someone opens the back door to your agent, looks in, synthesizes, updates it, closes it, and you as the user don't see the clutter"

### HERE.NOW VS GITHUB FOR DOCUMENTS

**Here.now:**
- Agent-first web hosting
- Single account view of all published content
- Simpler browsing than GitHub
- Quick HTTP POST API

**GitHub:**
- Permanent, free, standard
- Better for memory storage
- Can sync to local for Letabot processing
- But harder to browse as a human

**Demo:** Craig showed agent creating tidbit and publishing to here.now in real-time using run_code tool

### RUN CODE TOOL - POWERFUL CAPABILITY

**What It Does:**
- Creates sandbox environment (E2B.dev infrastructure)
- Writes and executes Python code on the fly
- Enables API interactions without pre-built integrations

**Example Workflow:**
1. Agent receives task
2. Writes Python code to interact with API
3. Executes in sandbox
4. Returns result

**ContextHub:** Andrew Ng's new tool - up-to-date API documentation for agents. Combined with run_code, enables "total agentic capability."
