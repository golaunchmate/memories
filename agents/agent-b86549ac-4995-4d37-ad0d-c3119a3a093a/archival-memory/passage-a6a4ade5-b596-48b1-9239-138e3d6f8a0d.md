Activepieces → Discord Notification Flow (July 17, 2026)

Laura set up an Activepieces workflow to automatically post new Letta agent messages to Discord. The flow: Schedule Trigger (1 min) → Store Get (last_msg_id) → HTTP Request (Letta API /v1/agents/{id}/messages?after={cursor}) → Code (parse + extract newest message ID) → Loop → Discord Send → Store Put (save newest msg ID).

KEY debugging findings:
1. Letta API `after` parameter DOES work — it's exclusive, returns only messages after the cursor. Messages are returned in ascending order (oldest first, newest last).
2. The cursor message ID MUST exist in the agent's message result set. Using a message ID from a different conversation/agent causes the API to ignore the `after` parameter and return all messages.
3. The actual bug: Activepieces variable referencing — the `after` query param was set to the Store Get step variable itself, not its output value (e.g., needed `{{steps.store_get.output.value}}` not just the variable name). This meant the `after` parameter was receiving garbage instead of the actual message ID.
4. Fix: Move query params from URL string into Activepieces' dedicated `queryParams` field, and properly reference the Store Get output.

Flow architecture: FLOW scope for persistent storage (persists between runs of same flow). 1-minute polling interval. Filters to assistant_message type only.
