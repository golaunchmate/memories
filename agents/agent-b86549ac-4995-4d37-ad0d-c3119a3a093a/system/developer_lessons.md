## DEVELOPER LESSONS (CRITICAL RULES)

See [[system/launchmate/gotchas]] for full gotchas list. Key rules:

1. **Tool params**: Never use `agent_id` as param name — use `target_agent_id`. Check via `get_letta_tool` before calling.
2. **A2A content**: Must be simple string, NOT array format.
3. **Letta API**: Cursor-based pagination (`after`/`before`), endpoint `https://api.letta.com`.
4. **Tool debugging**: Diagnose with `get_letta_tool` + `web_search` first. If still failing, bypass with `run_code_with_tools`.
5. **Tool editing**: After `edit_letta_tool`, code doesn't change until user refreshes. Don't repeatedly edit without waiting.
6. **Env vars**: Never add token params to tools. Use `os.environ.get("GITHUB_TOKEN")` inside tools. Available: GITHUB_TOKEN, LETTA_API_KEY, LETTA_BASE_URL, DISCORD_WEBHOOK_URL.
7. **Team transparency**: Always notify Discord after milestones. Don't wait for reminders.
8. **Archival memory**: Use `archival_memory_insert` for milestones, tool creation, significant progress.
9. **Memory management**: Never let blocks compact due to size — use `memory_update_size` or move to reference/.
10. **Bash vs code**: Use Bash for simple tasks, `run_code_with_tools` when you need env vars or complex Python.
11. **Windows/PowerShell**: Local machine is Windows. `&&` doesn't work — use `;`. Unix commands unavailable — use PowerShell cmdlets. `run_code_with_tools` runs in Linux container, not local.
12. **MemFS**: Memory blocks = MemFS files in `system/` directory. MemFS git IS enabled — changes are committed to the MemFS git repo. Files in `system/` are in-context; files in `reference/` are progressive disclosure (loaded on demand via `[[path]]` links). Some memory blocks (e.g., `shared_leaderboard`) are read-only and managed by the Letta server — they cannot be moved or deleted via filesystem operations.
13. **Search before claiming non-existence**: Before telling Laura a script/tool/file doesn't exist, search conversation history with `conversation_search`. She had to remind the agent about the `discord-route-consolidator-v2.py` script it had previously built.
14. **Discord routing**: Managed via `routing.yaml` and `accounts.json` in `.letta` directory. Letta Code has a built-in file watcher. Use strict channel gating (limiting open channels, disabling auto_thread_on_mention) instead of consolidator scripts. The consolidator approach was abandoned — it deleted conversations mid-response causing errors. **Routes are auto-generated by Letta Code** — do NOT manually create routes in `routing.yaml`; let the app handle it when channels are configured through the UI. **Account IDs are ephemeral** — they change on Letta Code restart; channel IDs are stable but account IDs are not. **Shared bot tokens work** — multiple agents can share the same Discord bot token with channel allowlisting (no `*` wildcard); non-matching adapters drop messages immediately with no token cost.
15. **Verify "current" status before sharing**: Before telling others what Laura is working on, search conversation history with `conversation_search` — the "Current focus areas" in memory can be stale. Laura corrected the agent on July 22, 2026 when it shared outdated focus areas with Craig on Discord.
16. **Memory sync to GitHub**: The `sync-agent-memory.ps1` script syncs 3 layers to `golaunchmate/memories`: core memory blocks (via Letta API), archival memory (via Letta API), and MemFS files (walked from local disk). Conversation history is excluded as overkill.
17. **#drops Discord channel** (`1506865147501871275`): Managed by the Drop Agent (`agent-82720585`), NOT the founder agent. Don't claim Discord delivery for drops goes through the founder agent — the Drop Agent owns the #drops channel.
18. **LETTA_API_KEY local limitation**: The API key is only available in the Letta agent runtime (via `run_code_with_tools`), NOT in local PowerShell. The sync script (`sync-agent-memory.ps1`) can sync MemFS files locally but cannot fetch core-memory blocks without the key. Run core-memory sync from within the agent environment or set the key locally. **Workaround proven July 22, 2026**: Use `run_code_with_tools` to fetch core-memory blocks via Letta API (`/v1/agents/{id}/core-memory`) and archival memory (`/v1/agents/{id}/archival-memory`), then upload to GitHub. This successfully synced blocks for all 3 secondary agents (Drop, AIC, Transcript).
19. **Dashboard GitHub API rate limiting**: The memory dashboard at `golaunchmate.github.io/memories/dashboard/` makes unauthenticated GitHub API calls from the browser (60/hour limit). Fetching the full repo tree multiple times per page load exhausts the rate limit. **Fix**: Cache the tree response from `loadAgents()` and reuse it in `loadAgentTree()`. Always check `response.ok` and handle 403 responses explicitly. The correct dashboard URL includes `/dashboard/` at the end.
20. **Discord reply discipline**: When Laura messages from Discord (`channel-notification source="discord"`), the FIRST action must be `MessageChannel(action="send", channel="discord", chat_id=...)`. Never respond with plain assistant text. This failed AGAIN on July 22, 2026 — Laura said "you didn't respond to my message in discord!" This is the #1 recurring failure pattern.
21. **Refactoring regressions**: When restructuring/reordering code blocks, verify all variable declarations survive the move. On July 22, 2026, swapping MemFS/legacy block render order accidentally dropped `let html = ''`, causing "html is not defined" across all agents. Always check that variable initialization statements aren't lost when moving code sections.
22. **`String.prototype.repeat(-1)` crash**: The "invalid count value: -1" dashboard error was NOT from GitHub rate limiting — it was from `'  '.repeat(depth - 1)` where `depth = 0` for top-level files (e.g., `human.md`) not in subdirectories. Fixed with `Math.max(0, depth - 1)`. When using `.repeat()`, always guard against negative values.
23. **Version indicators for deployment debugging**: When debugging GitHub Pages caching issues, add a visible version string (e.g., "v2.1" in sidebar) so users can confirm which version is loaded. Combine with cache-busting query params on asset URLs.
24. **Activepieces variable references**: In Activepieces, variable references must point to a step's OUTPUT (e.g., `{{steps.store_get.output.value}}`), not the variable/key name itself. Referencing the key name passes garbage. This was the #1 bug in Laura's Letta → Discord flow — the `after` cursor was getting garbage, causing the API to return all messages every run.
25. **Activepieces query params**: Use the `queryParams` field in the HTTP step for variables. Variables baked into URL strings don't interpolate reliably in Activepieces.
26. **Activepieces flow control**: The conditional branching step is called "Router" — not "Filter" or "Only Continue If" (those are Zapier terms). Must publish changes before they take effect.
27. **Letta API `include_return_message_types`**: The `/v1/agents/{id}/messages` endpoint supports `include_return_message_types` query param to filter at the API level (e.g., `?include_return_message_types=assistant_message`). This is more efficient than filtering in code.
28. **Letta API `after` cursor cross-agent**: The `after` parameter only works with message IDs from the SAME agent. Using a cursor from a different agent/conversation causes the API to silently ignore it and return all messages.
29. **Letta Cloud has no webhook support**: `STEP_COMPLETE_WEBHOOK` requires server-level env vars (not available on Cloud). PR #2646 for event streaming was closed. Polling is the only option for Cloud users.
30. **Activepieces Store Put + Router interaction**: If Store Put is gated behind a Router branch (e.g., `has_messages = true`), the cursor won't advance when there are no messages. Move Store Put outside the Router, or split into two branches. Also, when filtering message content, compute `last_message_id` from ALL messages so the cursor advances past filtered ones too.
